04

Light-mode inversion

The source rules state it but never showed it: on a light ground, banana stops being an accent color and becomes the field — Ink becomes the type. This is that inversion, applied, not described.

What inverted Void/Deep field → Banana field. Light/Soft type → Ink type. The o53 mark flips from a light outline to a dark one so it still reads as a watermark, not a logo lockup.
What held Instrument Serif at 0.92 line-height, the tracked micro-label, the mono sequence number, the diffuse-bloom absence of a hard gradient — none of that is dark-mode-specific, so none of it changes.
Rule check Rule 2 (palette doc): "On light grounds it inverts: banana becomes the field, Ink becomes the type." Confirmed above — Standout (#FFFFFF) still unused; the surface is Light (#F9F9FB) reserved space around the card, banana only fills the applied mockup itself.
05

What this turn added

Ten new specimens and applications, zero new hex values, zero new fonts. Everything above traces back to the same locked rules — this just proves they survive contact with real surfaces.

01 States, not just statics

Buttons and inputs now have hover, active, focus, error and disabled specimens — the source file only ever showed a resting state.

02 The chassis travels

Metadata station, bloom, grain and sequence number moved off the single desk-display mockup and onto a business card, a deck cover, and a profile header.

03 Light mode is real now

The inversion rule existed only as a sentence in the palette doc. It now exists as a rendered mockup that can be checked against that sentence directly.

Traces to Pairing 2C source specimen · desk-display mockup · palette table (Void through Banana) · documentation/application convention rules — nothing outside that set was introduced.
